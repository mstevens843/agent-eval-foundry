## Pairwise diversity

The existing five require per-name CAA authorization, live browser settling, persistent
provenance, cumulative delegated spending, and compatible fleet rollout respectively.
None maintains a partition checkpoint prefix, a causal sibling antichain, a dependency
compensation plan, a paginated cross-system conditional migration, or a bitemporal
interval integral. Reusing their authority RPC and export code does not reuse their
solution. A correct rollout implementation cannot solve graph recovery by renaming:
it lacks dependency ordering, shared-resource preservation and graph-difference planning.

The ten comparisons among the new five are also distinct: partition checkpoint prefixes
are ordered stream history, replica antichains are partial causal orders, release plans
are dependency orders over effects, ticket migration is population enumeration with
conditional field ownership, and temporal capacity is a two-time numerical query.
The first three share ordering ideas but have different state, operations, correctness
relations and valid repair algorithms. No single stable-id retry loop solves them.

## Construction and assurance plan

Each slot receives public multi-file code, runnable ordinary tests, fully stated API and
semantics, independent private truth/operation collection, deterministic interaction
scenarios, reference and separately implemented valid alternative, single-obligation
near misses, no-work/forged-output/overbroad-work and actual private-boundary controls.
Scenario selection is authored before final controls; development exposure is recorded.
No controls will be represented as indefinitely held out once inspected.

Reuse the existing PortfolioId → PackageRecord → protected operation runtime → assurance
→ recipient export path. Do not create another execution/readiness policy. Snapshot
source and exports remain outside Agent A's frozen source. Local validity, independent
review, authorization and model hardness remain separate statuses.

## Reserves and exclusions

Dormant rollback: reserve for a substantially different future construction; currently
too close to compatible rollout. Backup restoration: valuable reserve requiring actual
restoration/integrity and bounded data loss rather than a manifest classifier. Permission
brokers: reserve pending a genuinely multi-hop contract, not another scope-set kernel.
Clinical batch semantics inform generic ticket partial-result coverage without inventing
medical rules. Container/verifier attacks improve shared assurance, not task diversity.

Specific transfers: protected independent effects, positive-work and collateral gates,
legal ordering, strong near misses and valid alternative acceptance. Conceptual
transfers: local success can omit a required population or history relation.
Outbox ambiguity corrections remain intact; no model-personality claim or six proven
fair-capability failures is assumed. Existing four portfolio scenarios and imported
historical evidence are not modified.
