# Fourth portfolio construction — package-first, no subject trials

This source snapshot extends the preserved third-cohort V2 source. Earlier packages,
scenarios, controls and trial artifacts are not rewritten. Local validation is not
independent fairness review, a measured human solve, or evidence of model difficulty.

## Construction brief executed in this pass

Build five original, bounded repair services with outcome-based public contracts,
working multi-module starters and ordinary passing development tests. Implement
separate authoritative domain graders, references, genuinely different correct
strategies, deterministic scenarios, narrow semantic controls, no-work and forged
completion controls and protected-process denial probes. Validate through the real
package route, reproduce identities and recipient results, and retain raw evidence.
Never hide a rule, grade an author's preferred algorithm, or count an infrastructure
error as a solution failure. Do not make provider calls or authorize trials.

## Reused principles versus task-native construction

Reusable engineering: protected authority, authoritative positive work, acceptance of
alternate implementations, complete evidence capture, immutable package identities,
near-correct semantic mutants and bounded deterministic activation checks. The outbox
motivates checking multiple interacting obligations; it does not justify copying its
UNKNOWN receipts, random crashes or disputed historical rules into these domains.
Current outbox adjudications remain five specification-ambiguity labels and one
unresolved label. No new evidence here upgrades them.

Task-native details and complete bounds belong in each public SEMANTICS.md and api.d.ts.
The source implementations have naturally separated responsibilities, not arbitrary
file-count requirements. Standard libraries and any correct repair remain allowed.
The target expert repair time is roughly 2–3 hours, an author estimate pending
independent review. A short correct strategy is a risk to measure, not a strategy to ban.

## Evidence and completion requirements

Freeze generators before adding an additional validation control per package. Record
exposure honestly: inspected controls become regression controls, not pristine holdouts.
References and alternatives must pass every scenario and public test; starters must
pass public tests but fail semantically. Each negative control must hit its designated
obligation without crashing. Repeat builds and recipient validation must match.
Capture a per-package summary of actual failing witnesses, transferred principles,
remaining easiest plausible repairs and qualification blockers. Keep original evidence
unchanged. No finite control bank establishes universal absence of verifier bypasses.
