**Summary of the implementation** (`submission/subject.mjs`):
- Resolves every step's selector live via `app.query()`, never trusting `recordedNodeId` (R1).
- Reads preconditions live via `app.attr()` before running each step; a mismatch halts with `PRECONDITION_NOT_MET` (R2).
- Distinguishes `unreplayable` (node genuinely gone / ambiguous — `SELECTOR_UNRESOLVED`, `SELECTOR_AMBIGUOUS`) from `halted` (region still loading — `REGION_PENDING`; confirmation not yet shown — `CONFIRMATION_NOT_OBSERVED`), matching the "try later" vs. "re-record" distinction in SPEC.md.
- Requires an observed-and-accepted confirmation for any target with `data-opens-confirmation` (or an explicit `confirm` step) before considering the step done (R4).
- Keeps a module-level set of `${traceId}::${stepIndex}` for irreversible steps that already fired, so a second `replay()` call on the same trace skips re-invoking the mutating action entirely — verified this doesn't throw even if the target node is later removed (R5).
- Never calls `app.askModel` (R6).
- Every step audit reports the live-resolved node id, the observed pre/postcondition, and a named halt reason when applicable (R7).
