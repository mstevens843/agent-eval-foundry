# Prompt 4 — Five coherent professional package candidates

This pass constructs four new professional descendants and retains the strongest
defensible native CAA service. They are locally validated engineering artifacts,
not five established model-failure results. No provider call, subject trial, paid
rubric, official `/run` or `/cheat` was performed. Independent expert review and
destination qualification remain pending.

The machine-readable [verification record](verification/prompt-04.json) contains
the final package identities, control results, source snapshot and measured costs.
The [portfolio guide](../docs/professional-portfolio.md) documents runnable commands,
interfaces, every changed layer, evidence origins, rejected mechanisms and diversity.
The [pre-implementation designs](../docs/portfolio-design-records.md) preserve the
initial construction decisions and explicit easy-solve risks.

Each new workspace has navigable modules, a clear outcome contract, a plausible

## Integrity and alternative-solution review

The grading process owns private scenarios, real external operations, expected
state and reports. It never imports submitted modules. A fresh unprivileged child
requests documented operations through the existing bounded authority protocol.
Only its declared storage survives jobs. The grading container has no external
network and bounded CPU, memory, process count, output and wall time.

The browser uses actual Chromium event dispatch and a protected effect binding,
not a page-visible effect counter. Retained evidence includes operations, reports,
DOM snapshots and hashed Playwright ZIP traces. Every replay attempt is checked;
an early false completion cannot disappear behind a later correct attempt.

Memory, wallet and rollout grading checks each completed job's state/effect prefix,
not merely the last final state. The memory alternative uses an append-only journal,
bottom-up graph evaluation and reversed independent-publication order. The wallet
alternative uses an ephemeral allocation table and receipt-first reconciliation.
The rollout alternative stages the fleet before reconciling individual targets.
The browser alternative reinterprets receipts before resolving DOM state. These
are executed alternatives, not comments saying alternatives ought to be accepted.

Each new package has seven named negative controls plus the unchanged starter.
Controls cover one-obligation near misses, meaningful no-work/claim-only behavior,
and actual child read/write denial paired with a root-readable positive control.
At least three controls per package also have named non-activation cases that must
pass. All required runs must be free of invalid cells. The isolation control has
to execute and report actual denials; an empty execution list cannot satisfy it.

Export checks exact assurance coverage, variant digests, intact evidence bytes,
the full scenario/check population and raw semantic control outcomes. It does not
trust a saved pass label alone. Recipient proof repeats all twelve operations per
new package through that export's bundled CLI from an unrelated working directory.
It also rejects modified artifact and evidence bytes and confirms that a deliberately
crashing submission is classified invalid rather than a useful model failure.

## Construction corrections found during implementation

1. **Alternative overconstraint.** Memory publication order was initially checked
   more strictly than its contract required. Grading now compares independent
   publications without imposing author order; the reverse-order alternative passes.
2. **Temporal coverage.** Final-only comparisons could hide an earlier wrong job.
   New verifiers retain and check per-job prefixes; browser observations also carry
   attempt identity so an old observation cannot count as a current precondition.
3. **Assurance vacuity.** Semantic results require a real execution population, and
   export rechecks the actual control semantics and isolation evidence.
4. **Runtime reproducibility.** Two native CAA builds had identical source and image
   IDs but different archive hashes because Docker reversed top-level image entries.
   The producer now canonicalizes only those unordered JSON index lists using bounded
   random-access metadata reads. Image blobs and layer order are untouched. Fresh
   build and load tests verify the repaired boundary; earlier archives are retained.
5. **Bounded transport.** The shared local-process helper accepts bounded host input
   and preserves UTF-8 characters across stream chunks. Arbitrary submissions are
   copied once with file, byte, directory and depth bounds, rejecting symlinks,
   hardlinks and special files before execution.

The runtime-order change was made after freezing the four Node exports. Those
exports retain their exact validated bundled CLI and remain independently runnable;
the later change affects native archive production, not their submission route.
Their repeat builds and recipient checks refer to those retained bytes, not an
invented identity rebuilt from a later different CLI bundle. Future assembly from
the current source correctly creates a new full identity for changed tooling.

The first local development runs also exposed setup mistakes: an offline image
build with an uncached npm step, and missing CHOWN capability when creating the
child's state directory. These were fixed before the passing portfolio controls.
Later regression attempts caught a missing report/file-proof entry and stale
source-bound collector builds while the ledger was still being edited. Their
failed outputs remain retained; only the final frozen-source reruns count below.
None is model-hardness evidence.

## Scenario and control selection

Browser uses 16 deterministic scenarios; each other new candidate uses 12. These
are bounded interaction grids, not exhaustive validation of every permitted input.
They exercise useful work as well as refusal/preservation, with clear activation
and non-activation cases. The frozen generator hashes and consultation history are
in `data/portfolio-selection-ledger.json`.

Four additional controls—early-report, report-lineage, receipt-claim and
wrong-binding—were authored after generator membership was fixed. All were caught
on their first inspected results; none caused post-hoc scenario selection. They
are now regression controls, not a permanently unseen bank. This is a modest local
validation bank, not a claim of statistically independent discovery or model-axis
independence. More held-out professional cases remain useful future review work.

## Native CAA decision

The existing service already combines concurrent per-name association, freshness
boundaries, indeterminate authority, all-or-nothing orders, later writeback and
unrelated cache preservation. Existing correct alternatives and narrow controls
exercise those real interactions. This pass found no defensible additional business
constraint worth imposing solely to make the package appear harder.

More names would mainly add volume. Importing outbox-style unknowable receipts would
misstate this authority protocol. Prohibiting legal query/serialization strategies
would punish implementations rather than enforce the visible contract. The likely
short keyed-planner repair remains an explicit weakness, as Prompt 4 permits.

CAA's task source is unchanged; its newly frozen package identity changes because
the producer/runtime envelope changed. Historical source, trial and campaign bytes
were not rewritten. This is new local verification, not a new agent attempt.

## Local results and resource boundaries

Final frozen-source regression results: **138/138 focused tests and 15/15 actual
protected-route integration tests pass**, with no skips. Typecheck, lint (439
source/test files), full ESM/CJS/declaration build, public export loading, task-file
formatting and diff checks pass. Native CAA passes all **27/27 assurance operations**,
including its static-format tier, three correct implementation controls, negative
controls, process/artifact checks and activation/repeatability. Its fresh native
validation took approximately 370 seconds. Repeat build and exported task/runtime
bytes match; exported inspection is read-only. The broad historical repository
test suite is not claimed fully green.

Four Node candidates each pass twelve assurance operations: reference, alternative,
starter rejection, seven controls, visible-workspace tests and full reference repeat.
Both correct implementations pass the complete 52-scenario combined suite. The
same 48 operations pass again through exported recipient artifacts. Narrow controls
must fail the intended property; a no-op need not fail safety properties that doing
nothing genuinely satisfies.

On the recorded first final Node validation, total per-package assurance time was
approximately 79 seconds for browser, 12 seconds for memory, 8 seconds for wallet
and 6 seconds for rollout. Those totals include container startup and local checks,
not authoring effort or agent solve time. Shared concurrent host load matters; these
are observations, not throughput promises. Browser reference execution took about
11 seconds over 16 scenarios and 46 fresh child jobs.

All four use the same pinned Linux/arm64 Node/Playwright image. Its retained archive
is 974,869,504 bytes. CAA's two-image archive is 317,566,464 bytes. Each new grading
container is capped at 2 CPUs, 2 GiB, 256 PIDs; each submitted process at 45 seconds
and 4,000 operation requests. Submission capture is capped at 8 MiB/128 regular
files; metadata normalization reads at most two 4 MiB JSON entries rather than
loading the native archive into memory. Actual peak RSS was not measured.

Intermediate artifacts and raw failed/successful diagnostics are retained locally,
so development storage is materially larger than the five final exports. There
was no destructive cleanup. Shared-archive transport/deduplication and wider
cost profiling remain appropriate Prompt 7 work; copy-on-write is attempted, not
assumed to save space on every filesystem.

## Diversity, remaining risk and next owner

The five normalized solutions require different operations: keyed concurrent
authorization, a DOM replay interpreter, transitive revision closure, ordered
resource allocation and compatibility/health-qualified rollout. A prior patch does
not solve a new package after merely renaming its entities. Shared temporal identity
and independent collection are reusable principles, not proof of disjoint failure axes.

Easiest legal approaches remain straightforward to describe. A strong agent may
implement one correctly, especially with explicit small bounded domains. Useful
tests, several modules and many controls do not prove otherwise. No candidate is
labelled maximally hard. Author estimates of roughly 90–180 minutes require an
independent expert solve; reference execution is not that evidence.

The new Node artifacts are complete local foundry adapters, not certified Harbor/TB3
destination packages. Human-authored rubric material, destination adaptation/checks,
independent fairness/time review and all real standard/adversarial trials remain
separate. All stage decisions continue to block trial authorization and release.

Prompt 5 now has concrete public workspaces, arbitrary-submission entry points,
frozen package identities, reference/negative artifacts and protected graders to
integrate into reliable authorized execution. It must not infer spend permission.
Prompt 6 owns findings, withdrawal/transfer interpretation and package-first selection;
Prompt 7 owns broad integration, public cleanup and measured storage/performance work.
The existing `ADV_COUNTED_HASH_STALE` legacy checker-audit diagnostic remains pending
under its existing owner. It is not repaired by changing historical evidence.
